# Asahina 写作台

一个跑在本机的博客写作编辑器，专门为这个 Jekyll 博客准备。目标是把「写文章」从手写 Markdown 变成可视化编辑：左侧写、右侧按博客样式实时预览，写完直接写入 `_posts/`，需要时一键 `git add / commit / push`。

> 只监听 `127.0.0.1`，不需要登录，不会上传任何内容到第三方服务。

## 启动

```bat
editor\start.cmd
```

或者：

```bash
node editor/server.js --open
```

默认地址：<http://127.0.0.1:8090>

- 需要 Node.js（本机已有）。如果 8090 被占用，可以 `PORT=8091 node editor/server.js`。
- 所有依赖都已放在 `editor/vendor/`，断网也能用。
- `editor/` 已在 `_config.yml` 的 `exclude` 里，不会被 Jekyll 发布到博客。

## 功能范围

| 模块 | 能力 |
| --- | --- |
| 双模式编辑 | 富文本（contenteditable）与 Markdown 源码双向切换；富文本改动会自动转成 Markdown，Markdown 改动会重新渲染富文本 |
| 实时预览 | 右侧按博客正文样式渲染，支持标题、列表、引用、表格、代码高亮、KaTeX 公式（`$...$` / `$$...$$`） |
| 文章信息 | 标题、URL 文件名、发布时间、分类、标签、摘要、评论开关、封面图，自动生成 front matter |
| 图片 | 工具栏上传、拖拽到编辑区、直接粘贴剪贴板图片；保存到 `assets/images/uploads/YYYYMM/`，自动插入 Markdown/富文本 |
| 代码块 | 选择语言后插入 fenced code，预览用 highlight.js 高亮 |
| 表格 | 指定行列、是否表头，富文本下插入真实表格，Markdown 下插入管道表格 |
| 草稿 | 输入后 1.2 秒自动保存到 `editor/.drafts/`，支持草稿列表、载入、删除、断点恢复 |
| 已有文章 | 侧栏搜索并打开 `_posts/` 里的文章继续编辑；检测到 Liquid 语法会锁定 Markdown 模式，避免富文本转换破坏模板 |
| 导出 | 下载 Markdown、复制 Markdown、复制含 front matter 的全文 |
| 发布 | 「仅保存到 `_posts`」或「保存并推送上线」（git add / commit / push origin main），同名文件会二次确认 |
| 界面 | 浅色/深色主题、可拖拽分栏、字数与阅读时长、响应式（手机可切换侧栏和预览） |

## 核心操作流程

1. **启动**：双击 `editor\start.cmd`，浏览器会自动打开写作台。
2. **新建或打开**：默认是新文章；也可以从左侧「打开已有文章」里选一篇继续改，或点草稿箱里的历史草稿。
3. **填元信息**：标题、发布时间、分类、标签。`URL 文件名` 留空时由标题自动生成；摘要留空时 Jekyll 会自动截取正文。
4. **写正文**：
   - 富文本模式：直接用工具栏插入标题、加粗、列表、引用、链接、图片、代码块、表格、分隔线。
   - Markdown 模式：直接写源码，右侧同步预览；工具栏按钮会插入对应语法。
5. **传图**：点图片按钮、拖拽图片到编辑区，或直接 `Ctrl+V` 粘贴截图；封面图在左侧「文章设置 → 封面图」单独上传。
6. **保存草稿**：自动保存；也可以点「保存草稿」或 `Ctrl+S`。草稿在 `editor/.drafts/`，关掉浏览器再打开会恢复上次编辑。
7. **发布**：
   - 「发布到博客」→ 确认后写入 `_posts/` 并执行 git 提交、推送（会一并 `git add` 文中引用的本地图片和封面）；
   - 只想落盘不提交，用右侧下拉里的「仅保存到 `_posts`」；
   - 推送成功后 GitHub Pages 通常 1 分钟左右完成构建。
8. **导出**：不想现在发布，可以「导出 → 下载 Markdown」，文件带完整 front matter，之后手动放进 `_posts/` 也能用。

## 适用场景

- 写技术笔记、实验报告、课程总结：需要标题层级、表格、代码块、公式混排。
- 写长文时不想被 Markdown 语法打断思路：先用富文本写，最后切 Markdown 微调。
- 文章里有截图/公式/表格：粘贴即上传，预览与博客最终样式基本一致。
- 维护旧文章：直接打开 `_posts/` 里的文件改，发布时覆盖原文件，不改变 URL。
- 不适合：多人协作、云端同步、手机端重度写作（移动端可用，但复杂排版仍建议桌面）。

## 数据与安全

- 服务只绑定 `127.0.0.1:8090`，没有账号体系；**不要把它暴露到公网或局域网**。
- 草稿：`editor/.drafts/*.json`（已在 `editor/.gitignore` 中忽略）。
- 上传图片：`assets/images/uploads/YYYYMM/`，会随博客一起提交。
- 发布：写 `_posts/YYYY-MM-DD-<标题>.md`；推送使用本机已有的 git 凭据，服务本身不保存任何密码。
- Markdown/富文本转换在浏览器本地完成，不会把文章内容发到外部服务。
- 打开含 Liquid（`{{ ... }}`）的旧文章时会锁定 Markdown 模式，富文本按钮不可用，避免 `relative_url` 等模板语法被转换丢失。

## 目录

```text
editor/
├─ index.html          界面
├─ styles.css          主题与布局
├─ app.js              双模式编辑、预览、草稿、发布
├─ server.js           零依赖 Node 服务（静态资源 + API）
├─ start.cmd           Windows 启动脚本
├─ vendor/             marked / turndown / DOMPurify / highlight.js / KaTeX
└─ .drafts/            本地草稿（不提交）
```

## API 一览（本地）

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/meta` | 现有分类、标签、文章列表 |
| GET | `/api/post?file=` | 读取一篇 `_posts` 文章 |
| GET/POST | `/api/drafts` | 草稿列表 / 保存草稿 |
| GET/DELETE | `/api/drafts/:id` | 读取 / 删除草稿 |
| POST | `/api/upload` | 上传图片（base64） |
| POST | `/api/publish` | 写入 `_posts`，可选 commit + push |

## 已知限制

- 富文本模式里直接输入 `- `、`1. ` 不会自动变成列表，请用工具栏的列表按钮；预览仍会把 `- ` 当普通文本。
- 富文本模式不渲染公式，`$...$` 以源码显示；右侧预览会正常渲染。保存时会保护公式源码，不会把 `\neq` 转义成 `\\neq`。
- 含 Liquid（`{{ ... }}` / `{% ... %}`）的文章会锁定 Markdown 模式，富文本按钮不可用，避免 `relative_url` 被转义成 `relative\_url`。
- 不做图片压缩/裁剪，封面建议自己准备 16:10（如 800×500）。
- 推送依赖本机 git 凭据与网络；失败时文件已保存，日志会显示在弹窗里。
- 没有版本历史；覆盖同名文章前会二次确认。
