## 实验目的

  1.理解进程的基本概念及它与程序的区别和联系；

  2.了解进程控制块（PCB）的一般属性和作用；

  3.理解原语的含义，掌握常用的进程控制原语；

  4.通过模拟实验深刻理解进程基本状态的转换过程。

## 一、进程简介

### 1. 进程的定义

进程至今没有一个统一的定义，但可以从不同角度来描述：

- 进程是程序的一次执行；
- 进程是可以和其他计算并发执行的计算；
- 进程是一个程序及其数据在处理机上顺序执行时发生的活动；
- 进程是程序在一个数据集合上的运行过程，是系统进行资源分配和调度的一个独立单位；
- 进程是进程实体的一次活动。

### 2. 进程的特点

| 特性 | 说明 |
| --- | --- |
| 动态性 | 进程是程序的一次执行过程，有创建、执行、阻塞、撤销的生命周期，这是进程最重要的特性 |
| 并发性 | 不同进程的动作在时间上可以重叠，多个进程可以并发执行 |
| 独立性 | 进程是独立运行和申请资源的基本单位；引入线程后，进程仍是独立拥有资源的基本单位 |
| 异步性 | 进程以各自独立、不可预知的速度推进，系统需要提供同步与互斥机制 |
| 结构特性 | 进程实体由程序、数据和 PCB 三部分组成 |

## 二、进程控制块（PCB）

PCB 是系统为了描述和控制进程运行而定义的数据结构，是进程实体的一部分，也是进程存在的唯一标志。操作系统通过 PCB 感知进程的存在，并根据 PCB 对并发执行的进程进行控制和管理。

### 1. PCB 的作用

1. **标识进程的存在**：创建进程时建立 PCB，进程结束时回收 PCB，进程随之消亡。
2. **提供可并发执行的独立单位**：没有 PCB 的程序不能并发执行。
3. **提供控制和管理进程所需的信息**：PCB 保存进程的当前状态、资源、优先级等全部描述信息。

### 2. PCB 中的信息

| 信息 | 作用 |
| --- | --- |
| 进程标识符 | 系统内部标识进程的唯一编号，也可有供用户使用的外部标识符 |
| 现行状态 | 标明进程当前处于就绪、执行还是阻塞，是调度的依据 |
| 处理机现场保留区 | 保存 PSW、程序计数器、通用寄存器和栈指针等，便于恢复执行 |
| 程序和数据地址 | 记录进程的程序与数据在内存或外存中的位置 |
| 进程资源清单 | 记录打开的文件、占用的 I/O 设备等除 CPU 外的资源 |
| 进程优先级 | 基于优先级的调度算法的主要依据 |
| 同步与通信机制 | 信号量、信箱、消息队列等指针 |
| PCB 链接字 | 指向同一队列中下一个进程的 PCB，队尾为空 |
| 其他信息 | 父子进程关系、记账信息、占用 CPU 时间、所属用户等 |

## 三、进程的基本状态及转换

### 1. 三种基本状态

- **就绪状态**：进程已分配到除 CPU 以外的所有必要资源，只要获得处理机便可立即执行。系统中可以同时有多个就绪进程。
- **执行状态**：进程已获得处理机，程序正在处理机上执行。单处理机系统中同一时刻只有一个进程处于执行状态。
- **阻塞状态**：正在执行的进程因等待某事件（请求 I/O、申请缓冲区、等待信号或消息等）而无法继续执行，放弃处理机进入暂停状态，也称等待状态。

### 2. 状态转换

| 转换 | 触发条件 | 说明 |
| --- | --- | --- |
| 就绪 → 执行 | 进程调度 | 调度程序为进程分配处理机 |
| 执行 → 就绪 | 时间片用完 | 暂停执行，重新回到就绪队列 |
| 执行 → 阻塞 | 等待事件发生 | 进程主动让出处理机并等待 |
| 阻塞 → 就绪 | 等待的事件发生 | 被唤醒后进入就绪队列，等待再次调度 |

三种基本状态的转换可以概括为：就绪 --调度--> 执行；执行 --时间片完--> 就绪；执行 --等待事件--> 阻塞；阻塞 --事件发生--> 就绪。

## 四、进程控制原语

原语是操作系统内核中由若干条机器指令构成、用于完成特定功能的过程，执行时不可分割，具有原子性。现代操作系统通常采用屏蔽中断的方法保证原语执行的不可分割性，这对解决进程同步与互斥问题非常重要。

进程控制原语用于控制进程生命周期和状态转换，主要包括创建、撤销、阻塞、唤醒、挂起、激活六种；本实验涉及前四种：

| 原语 | 主要操作步骤 |
| --- | --- |
| 进程创建 | 申请空闲 PCB 并获得内部标识 → 分配内存等资源 → 初始化 PCB（状态常设为就绪）→ 插入就绪队列 |
| 进程撤销 | 检索 PCB 并读出状态 → 终止执行或移出队列 → 递归撤销子孙进程 → 归还资源 → 释放 PCB → 必要时转调度 |
| 进程阻塞 | 终止调用者自身执行 → 置为阻塞态 → 插入相应阻塞队列 → 转进程调度 |
| 进程唤醒 | 找到被唤醒进程 → 从阻塞队列移出 → 置为就绪态 → 插入就绪队列 |

## 五、进程控制模拟实现

### 1. 实验步骤

1. 进入工作目录 `/headless/Desktop/os/project1`。
2. 以 `fcfs.c` 为基础修改，另存为 `processmanagehard.c`。
3. 用 Visual Studio Code 打开该文件，定义就绪队列和阻塞队列。
4. 补全阻塞进程 `block()` 与唤醒进程 `wake()` 的功能。
5. 编译并运行程序，检验代码正确性：

```bash
gcc processmanagehard.c -o processmanagehard
./processmanagehard
```

6. 通过回车、`s`、`w` 观察进程状态和两条队列的变化，直到所有进程执行完毕。

### 2. 两条进程队列

程序用两条链表分别管理就绪进程和阻塞进程：

```c
PCB *ready = NOTHING, *pfend = NOTHING, *p = NOTHING,
    *stop = NOTHING, *stopend = NOTHING;
```

- `ready` / `pfend`：就绪队列的队首和队尾；
- `stop` / `stopend`：阻塞队列的队首和队尾。

进程创建和撤销此前已经实现，本实验新增的是阻塞与唤醒，因此需要同时维护两条队列的队首、队尾指针。

### 3. 创建与撤销

`fcfs()` 把新进程插入就绪队列尾部：

```c
void fcfs() // 插入进程
{
    if (!ready) {
        ready = p;
        pfend = p;
    } else {
        p->link = pfend->link;
        pfend->link = p;
        pfend = p;
    }
}
```

`destroy()` 在进程运行结束后释放其 PCB，并让就绪队首后移：

```c
void destroy()
{
    printf("\n进程[%s]已完成.\n", ready->name);
    p = ready;
    ready = ready->link;
    free(p);
}
```

### 4. 阻塞与唤醒（实验框架）

文档给出的待补全框架：

```c
void block()
{
    if (!stop) {
        ready->state = 'b';
        // 待补全
    } else {
        ready->state = 'b';
        // 待补全
    }
}

void wake()
{
    if (stop == NOTHING) {
        printf("\n阻塞队列为空，请进行其他操作");
        return;
    } else {
        if (ready != NOTHING) {
            // 待补全
        } else {
            // 待补全
        }
        // 待补全
    }
}
```

补全后的参考实现：

```c
void block()
{
    if (ready == NOTHING) {
        printf("\n就绪队列为空，没有可阻塞的进程");
        return;
    }

    p = ready;                  // 取就绪队首
    ready = ready->link;        // 就绪队列出队
    if (ready == NOTHING) pfend = NOTHING;

    p->state = 'b';             // 置为阻塞态
    p->link = NOTHING;

    if (stop == NOTHING) {      // 阻塞队列为空
        stop = p;
        stopend = p;
    } else {                    // 挂到阻塞队列队尾
        stopend->link = p;
        stopend = p;
    }
}

void wake()
{
    if (stop == NOTHING) {
        printf("\n阻塞队列为空，请进行其他操作");
        return;
    }

    p = stop;                   // 取阻塞队首
    stop = stop->link;          // 阻塞队列出队
    if (stop == NOTHING) stopend = NOTHING;

    p->state = 'r';             // 恢复为就绪态（按原程序的状态标志）
    p->link = NOTHING;

    if (ready != NOTHING) {     // 就绪队列非空，挂到队尾
        pfend->link = p;
        pfend = p;
    } else {                    // 就绪队列为空
        ready = p;
        pfend = p;
    }
}
```

> `state` 的具体字符以原程序约定为准；这里沿用文档中 `'b'` 表示阻塞，`'r'` 表示就绪。

### 5. 交互流程

程序通过键盘输入驱动进程状态变化：

| 输入 | 行为 |
| --- | --- |
| 回车 | 检查就绪队列和阻塞队列；就绪队列非空则执行队首进程，否则等待 |
| `s` | 阻塞就绪队首进程，将其添加到阻塞队列队尾 |
| `w` | 唤醒阻塞队首进程，将其添加到就绪队列队尾 |

如此往复，直至所有进程执行完毕，程序停止。

## 六、实验结论

1. **进程与程序的区别**：程序是静态的指令集合，进程是程序的一次执行，具有动态性、并发性、独立性和异步性；进程实体由程序、数据和 PCB 三部分组成。
2. **PCB 是进程存在的唯一标志**：系统通过 PCB 感知、调度和管理进程，PCB 中保存标识符、状态、处理机现场、资源、优先级和队列链接等全部描述信息。
3. **三种基本状态由特定事件驱动**：调度使就绪转为执行，时间片用完使执行回到就绪，等待事件使执行转为阻塞，事件发生使阻塞回到就绪。
4. **进程控制原语必须原子执行**：创建、撤销、阻塞、唤醒本质上是对 PCB 的申请、初始化、入队、出队和释放，中间状态被并发打断就可能破坏队列一致性。
5. **阻塞不等于撤销**：被阻塞的进程仍然存在并占用资源，只是让出处理机；唤醒后重新进入就绪队列，等待下一次调度。
6. **队列实现的关键在边界处理**：要维护好队首/队尾指针，并正确处理空队列、出队后队列变空、入队到队尾这三种情况，否则会出现指针丢失或队列断裂。

## 七、思考与延伸

文档留了一个问题：程序默认只阻塞或唤醒队首进程，如果要阻塞或唤醒指定进程，该如何实现？

一种直接做法是遍历队列，按进程标识符（pid 或 name）查找目标 PCB，同时记录前驱节点；找到后把前驱的 `link` 指向目标的后继，再把目标插入另一条队列的队尾。这样查找是 O(n)，但不需要额外的数据结构。

如果进程数量较多，可以再维护一张“pid → PCB”的哈希表，把查找降到 O(1)；代价是创建、撤销、阻塞、唤醒时都要同步维护这张表，否则表项会和实际队列不一致。
