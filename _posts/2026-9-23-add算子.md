# 这是我学习的第一个算子——双输入加法算子

**此算子一共分为3部分，分别为** 
- Kernel类（核心逻辑）
- 核函数入口
- Host侧调用
接下来我就这三部分进行详细解析

## 1.Kernel类

### 问题提出
1.为什么 tileLength 要除以 BUFFER_NUM，而 loopCount 要乘以 BUFFER_NUM？

2.CopyIn 里如果先 EnQue 再 DataCopy，会发生什么？

3.Compute 里 Add 那一行执行完，zLocal 里的结果一定算好了吗？

4.CopyOut 里 DataCopy 的第一个参数是 zGm[...]，为什么是目标在前？

5.如果不加 blockLength * GetBlockIdx() 偏移，多核跑会怎样？

```cpp
constexpr int32_t BUFFER_NUM = 2;

struct AddTilingData
{
    uint32_t totalLength;
    uint32_t tileNum;
};

class KernelAdd {
public:
    __aicore__ inline KernelAdd() {}

    __aicore__ inline void Init(GM_ADDR x, GM_ADDR y, GM_ADDR z,
                                uint32_t totalLength, uint32_t tileNum)
    {
        this->blockLength = totalLength / AscendC::GetBlockNum();
        this->tileNum = tileNum;
        this->tileLength = this->blockLength / tileNum / BUFFER_NUM;

        // 每个核偏移到自己那一段
        xGm.SetGlobalBuffer((__gm__ float *)x + this->blockLength * AscendC::GetBlockIdx(),
                            this->blockLength);
        yGm.SetGlobalBuffer((__gm__ float *)y + this->blockLength * AscendC::GetBlockIdx(),
                            this->blockLength);
        zGm.SetGlobalBuffer((__gm__ float *)z + this->blockLength * AscendC::GetBlockIdx(),
                            this->blockLength);

        pipe.InitBuffer(inQueueX, BUFFER_NUM, this->tileLength * sizeof(float));
        pipe.InitBuffer(inQueueY, BUFFER_NUM, this->tileLength * sizeof(float));
        pipe.InitBuffer(outQueueZ, BUFFER_NUM, this->tileLength * sizeof(float));
    }

    __aicore__ inline void Process()
    {
        int32_t loopCount = this->tileNum * BUFFER_NUM;
        for (int32_t i = 0; i < loopCount; i++) {
            CopyIn(i);
            Compute(i);
            CopyOut(i);
        }
    }

private:
    __aicore__ inline void CopyIn(int32_t progress)
    {
        AscendC::LocalTensor<float> xLocal = inQueueX.AllocTensor<float>();
        AscendC::LocalTensor<float> yLocal = inQueueY.AllocTensor<float>();
        AscendC::DataCopy(xLocal, xGm[progress * this->tileLength], this->tileLength);
        AscendC::DataCopy(yLocal, yGm[progress * this->tileLength], this->tileLength);
        inQueueX.EnQue(xLocal);
        inQueueY.EnQue(yLocal);
    }

    __aicore__ inline void Compute(int32_t progress)
    {
        AscendC::LocalTensor<float> xLocal = inQueueX.DeQue<float>();
        AscendC::LocalTensor<float> yLocal = inQueueY.DeQue<float>();
        AscendC::LocalTensor<float> zLocal = outQueueZ.AllocTensor<float>();
        AscendC::Add(zLocal, xLocal, yLocal, this->tileLength);
        outQueueZ.EnQue<float>(zLocal);
        inQueueX.FreeTensor(xLocal);
        inQueueY.FreeTensor(yLocal);
    }

    __aicore__ inline void CopyOut(int32_t progress)
    {
        AscendC::LocalTensor<float> zLocal = outQueueZ.DeQue<float>();
        AscendC::DataCopy(zGm[progress * this->tileLength], zLocal, this->tileLength);
        outQueueZ.FreeTensor(zLocal);
    }

private:
    AscendC::TPipe pipe;
    AscendC::TQue<AscendC::TPosition::VECIN, BUFFER_NUM> inQueueX, inQueueY;
    AscendC::TQue<AscendC::TPosition::VECOUT, BUFFER_NUM> outQueueZ;
    AscendC::GlobalTensor<float> xGm, yGm, zGm;
    uint32_t blockLength;
    uint32_t tileNum;
    uint32_t tileLength;
};
```

**它是整个算子的核心部分，实现了以下几个功能**
- 每个核分到多少数据
- 数据怎么从 GM（全局内存）搬到 UB（片上缓存）
- 怎么算
- 结果怎么从 UB 搬回 GM

**逻辑分成以下几个部分**
- Init:初始化算好每个核多少数据，并给GM张量按核号偏移好。
- Process:主循环
- CopyIn:读入数据，将数据从GM搬到UB，方便每个核读取，然后EnQue放进输入队列
- Compute:计算的核心逻辑，从队列中取出数据调用AscendC::Add计算，然后将结果添加到输出队列
- CopyOut:从输出队列取出结果，然后通过DataCopy搬回GM

## 2.核函数入口

### 问题提出
1.为什么核函数要加 extern "C"？不加会怎样？

2.GM_ADDR tiling 传进来的是地址还是结构体本身？为什么不能直接传结构体？

3.`((__gm__ AddTilingData *)tiling)->totalLength 这一句里，__gm__ 的作用是什么？去掉会怎样？`

4.KERNEL_TASK_TYPE_DEFAULT(KERNEL_TYPE_AIV_ONLY) 如果不写，会有什么问题？

5.host 侧 add_custom<<<blockDim, nullptr, stream>>>(xDevice, yDevice, zDevice, tilingDevice) 里，如果 xDevice 和 yDevice 写反了，运行时会不会报错？结果会怎样？

```cpp
extern "C" __global__ __aicore__ void add_custom(GM_ADDR x, GM_ADDR y, GM_ADDR z, GM_ADDR tiling)
{
    KERNEL_TASK_TYPE_DEFAULT(KERNEL_TYPE_AIV_ONLY);

    KernelAdd op;
    op.Init(x, y, z,
            ((__gm__ AddTilingData *)tiling)->totalLength,
            ((__gm__ AddTilingData *)tiling)->tileNum);
    op.Process();
}
```

**作为NPU上被启动的函数本身**
- 声明任务类型（KERNEL_TASK_TYPE_DEFAUL(KERNEL_TYPE_AIV_ONLY)）
- 创建一段定义的 KernelAdd op
- 调用 op.Init()和op.Process()

**关键点**
- extern "C":保证函数名不被C++改名，Host侧才能按名字找到
- `__global__`:表示这是 kernel 函数（Host 可启动，Device 上执行）
- `__aicore__`:表示在 AI Core 上执行
- `GM_ADDR`:通用的 Device 全局内存地址类型（本质是__gm__uint8_t*）
- KERNEL_TASK_TYPE_DEFAULT(KERNEL_TYPE_AIV_ONLY):声明这个kernel 只用 AIV（向量核），不用 AIC（矩阵核），影响调度

## Host侧调用

### 问题提出
1.aclInit、aclrtSetDevice、aclrtCreateStream 三者的顺序能颠倒吗？为什么？

2.aclrtMalloc 分配的 xDevice 和 new uint8_t[] 分配的 zHost，释放方式为什么不同？

3.aclrtSynchronizeStream(stream) 如果不写，会发生什么？

4。std::vector<float> z((float*)zHost, (float*)(zHost + totalByteSize)) 里，为什么第二个指针是 zHost + totalByteSize 而不是 zHost + totalLength？

5.aclrtMemcpy 的参数顺序是 (dst, dstSize, src, srcSize, 方向)，如果把 xDevice 和 x.data() 写反了，会发生什么？

```cpp
std::vector<float> run_add(std::vector<float> &x, std::vector<float> &y)
{
    constexpr uint32_t blockDim = 1;
    uint32_t totalLength = x.size();
    size_t totalByteSize = totalLength * sizeof(float);
    AddTilingData tiling = {totalLength, 8};

    aclrtStream stream = nullptr;
    aclInit(nullptr);
    aclrtSetDevice(0);
    aclrtCreateStream(&stream);

    uint8_t *xDevice = nullptr, *yDevice = nullptr, *zDevice = nullptr, *tilingDevice = nullptr;
    aclrtMalloc((void **)&xDevice, totalByteSize, ACL_MEM_MALLOC_HUGE_FIRST);
    aclrtMalloc((void **)&yDevice, totalByteSize, ACL_MEM_MALLOC_HUGE_FIRST);
    aclrtMalloc((void **)&zDevice, totalByteSize, ACL_MEM_MALLOC_HUGE_FIRST);
    aclrtMalloc((void **)&tilingDevice, sizeof(AddTilingData), ACL_MEM_MALLOC_HUGE_FIRST);

    aclrtMemcpy(xDevice, totalByteSize, x.data(), totalByteSize, ACL_MEMCPY_HOST_TO_DEVICE);
    aclrtMemcpy(yDevice, totalByteSize, y.data(), totalByteSize, ACL_MEMCPY_HOST_TO_DEVICE);
    aclrtMemcpy(tilingDevice, sizeof(AddTilingData), &tiling, sizeof(AddTilingData),
                ACL_MEMCPY_HOST_TO_DEVICE);

    add_custom<<<blockDim, nullptr, stream>>>(xDevice, yDevice, zDevice, tilingDevice);
    aclrtSynchronizeStream(stream);

    uint8_t *zHost = new uint8_t[totalByteSize];
    aclrtMemcpy(zHost, totalByteSize, zDevice, totalByteSize, ACL_MEMCPY_DEVICE_TO_HOST);
    std::vector<float> z((float *)zHost, (float *)(zHost + totalByteSize));

    aclrtFree(xDevice); aclrtFree(yDevice); aclrtFree(zDevice); aclrtFree(tilingDevice);
    delete[] zHost;
    aclrtDestroyStream(stream);
    aclrtResetDevice(0);
    aclFinalize();

    return z;
}
```

**主要负责什么**
*在 CPU 侧把整个算子调用流程串起来*
- 初始化 ACL 环境、创建 stream
- 在 Device 上分配输入/输出/tiling 内存
- 把 Host 数据拷到 Device
- 启动 kernel
- 等 kernel 跑完
- 把结果拷回 Host
- 释放内存、清理环境

**为什么需要**
NPU 不能自己凭空开始跑，必须由 Host 侧准备好数据、内存、参数，然后显式启动。这一整段就是「准备 → 启动 → 收尾」的完整生命周期。
